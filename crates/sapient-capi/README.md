# sapient-capi — the C ABI

The stable C surface for embedding SAPIENT. This is what every non-Rust, non-mobile
language binds to: Python (cffi), Go (cgo), Node (N-API), C#, Java, Julia, Zig.

- **Header:** [`include/sapient.h`](include/sapient.h) — the canonical declaration
- **Guide:** [`docs/C-ECOSYSTEM.md`](../../docs/C-ECOSYSTEM.md)
- **Example:** [`examples/c-chat`](../../examples/c-chat)

```bash
cargo build --release -p sapient-capi     # → target/release/libsapient.{a,dylib,so}
scripts/install-capi.sh --prefix /usr/local   # + header, pkg-config, CMake config
```

```c
#include "sapient.h"

sapient_error_t *err = NULL;
sapient_options_t opts = sapient_options_default();
sapient_session_t *s = sapient_session_load("smollm2-135m-q4", &opts, &err);

char *reply = NULL;
sapient_chat(s, "Hello!", &reply, &err);
puts(reply);

sapient_string_free(reply);
sapient_session_free(s);
```

## Why not `sapient-ffi`?

`sapient-ffi` exports **UniFFI scaffolding** — `RustBuffer`, generated handles, and a
contract checksum that aborts on mismatch (hence its `uniffi = "=0.29.3"` exact pin).
That is the right design for generating Swift and Kotlin, and the wrong thing to
`#include`. This crate is hand-written, versioned, and stable.

| | `sapient-ffi` | `sapient-capi` |
|---|---|---|
| Consumers | Swift, Kotlin, React Native | C, C++, and every language with a C FFI |
| Surface | generated by UniFFI | hand-written `sapient.h` |
| Stability | tracks the UniFFI release | `SAPIENT_API_VERSION`, gated in CI |

## Invariants

Change these and downstream bindings break — often silently.

1. **No panic crosses the boundary.** Every `extern "C"` entry point goes through
   `guard_status` (status-code returns) or `guard` (value returns), which convert a panic
   into `SAPIENT_ERR_PANIC`. A panic unwinding into C is undefined behaviour.
2. **`guard_status` returns the error's own code**, never a fixed sentinel — otherwise a
   generation failure is indistinguishable from a bad argument. Regression-tested by
   `guard_status_returns_the_real_code_not_a_sentinel`.
3. **Every returned pointer has exactly one matching free.** `sapient_string_free`,
   `sapient_error_free`, `sapient_session_free`. The two exceptions — `sapient_version`
   and `sapient_error_message` — are library-owned and documented as such in the header.
4. **Futures run on runtime workers, never `block_on` on the caller.** `Pipeline` uses
   `tokio::task::block_in_place`, which panics on a non-worker thread. Same rule as
   `sapient-ffi`; see `docs/MOBILE.md`.
5. **The stream is consumed on the caller's thread.** `blocking_recv` must not run on a
   runtime worker. Dropping the receiver is the cancellation signal — no engine API needed.
6. **Header and implementation must agree.** `tests/abi_surface.rs` compares the
   `#[no_mangle]` exports, the header declarations, and a committed snapshot, plus every
   status/backend constant and the ABI version. Adding a function means updating all
   three deliberately; renaming or removing one means bumping `SAPIENT_API_VERSION` in
   **both** `src/lib.rs` and `include/sapient.h`.

## Tests

```bash
cargo test -p sapient-capi          # 13 unit + 5 ABI-surface gates
cd examples/c-chat && make          # the real link check
```

The unit tests cover the option→sampler mapping, backend constants, panic conversion,
NULL handling on every entry point, interior-NUL escaping, and catalog access. They do
**not** download models; the example does.
